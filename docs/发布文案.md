## 二、V2EX

**节点**：`/go/create`（分享创造）或 `/go/programmer`

**标题**：
> 把 80 页 PPT 模板拆成了 44 个可参数化的图形原子，一套 JSON 同时出 PPTX 和网页

**正文**：

```
做方案画逻辑图这件事，重复劳动太多了。一套 80 页的方案，光画图能占三分之一时间，
改一版还要全篇返工。

我手上有几份参考模板（29 / 32 / 80 页），就把那 80 页一份一页拆开，想看看到底有几种画法。

结论有点反直觉：80 页里只有 14 种逻辑骨架。
分层平台一种就占了 20 页，中心辐射 16 页，同心环 11 页，左右对称 11 页……

再往下拆，骨架都由同一批零件拼的：卡片、胶囊、徽标、扇形、弧、虚线。
最后归成 44 个原子 + 20 个线性图标。

于是做了个参数化的版本：每个原子只描述"怎么画"，参数是层数、条目、行列、配色；
一份 JSON 同时产出：

- 可编辑 PPTX（原生形状，不是图片）
- 网页 SVG（放大不糊）

技术上有几个坑：
1. python-pptx 没有渐变/阴影 API，得直接往 spPr 里注入 OOXML
2. PowerPoint 不支持文字沿路径，环形标签只能逐字定位逐字旋转
3. 两条渲染管线能力不对等（SVG 有滤镜、PPTX 只有近似）

还写了个排版 lint：逐页查越界、文字溢出、文本框重叠。目前 44 原子图鉴 44 页、
1.0 雏形 24 页、80 页验收册 80 页，全部 0 问题。

仓库（MIT）：https://github.com/tonymingyang-prog/definition-logic

不装环境也能看效果，网页版在 examples/ 下，双击就能翻。

欢迎拍砖，特别是"哪几个原子观感还不行"这种意见。
```
