# 80 页 PPT 模板，最后只剩 44 个原子

> 一篇讲清楚「定义逻辑图」是怎么被拆出来的：80 页模板 → 14 种逻辑骨架 → 44 个可参数化原子。
> 仓库：https://github.com/tonymingyang-prog/definition-logic （MIT）

## 一、起点：一页一页地画

做咨询方案、架构设计、年度汇报，绕不开一件事——**画逻辑图**。

分层架构、中心辐射、同心环、矩阵、时间轴、泳道、漏斗……每一页都要重新画：画形状、对齐、调字、配颜色。改一版，全篇返工。一套 80 页的方案，光画图能占掉三分之一的时间。

我手上有三份参考模板：29 页、32 页，还有一份 **80 页的蓝色静态逻辑图模板**。加起来 141 页，每一页都是成熟的"汇报级"排版。

问题是：**怎么把它变成可复用的东西？**

## 二、第一个发现：80 页里只有 14 种骨架

我先做了一件很笨的事：把 80 页一页一页拆开，记录每页的图形构成。

拆完发现一个反直觉的事实——

| 指标 | 数量 |
|---|---|
| 模板页数 | 80 |
| 逻辑骨架 | **14 类** |
| 不同原子组合 | 66 种 |
| 实际用到的原子 | 32 个 |

分布是这样的：

- 分层平台 **20 页**
- 中心辐射 **16 页**
- 同心环 **11 页**
- 左右对称 **11 页**
- 横向链路 7 页
- 半环 / 多层弧 4 页
- 金字塔 3 页、矩阵 2 页
- 时间轴 / 对比 / 漏斗 / 词云 / 等距 / 蜂窝 各 1 页

**"分层平台"一种骨架，就占了四分之一的页数。**

所以"80 页"不是 80 种图，而是 **14 种骨架 × 内容 × 装饰**。同一套几何，换层数、换条目、换配色，就是新的一页。

这就是为什么你翻模板会觉得"每张图都长得不一样"，又觉得"好像都差不多"。

## 三、第二个发现：骨架还能再拆

14 类骨架里，真正独立的东西更少——它们都由同一批"零件"拼出来的：

一个圆角卡片、一个胶囊标签、一个序号徽标、一条虚线、一个扇形、一条弧。

拆到最后，归成 **44 个原子**：

| 类别 | 数量 | 代表 |
|---|---|---|
| 结构 / 全景 | 17 | 中心辐射、矩阵、金字塔、平台叠层、环形体系、漏斗、蜂窝、扇区环带、多层同心弧、等距立体 |
| 流程 / 时序 | 6 | V 形流程、节点步骤流、泳道带、时间轴、纵向清单、看板分栏 |
| 面 / 卡片 | 12 | 标准卡、图标卡、指标卡、页签、标签、徽标、横幅、进度条 |
| 框架 / 容器 | 3 | 虚线分区、侧边括号、纵向栏位 |
| 文字 / 标题 | 2 | 标题块、结论条 |
| 装饰 / 氛围 | 4 | 点阵弧、虚线轨道、柔光底衬、角标刻度 |

再加上 **20 个线性图标**（客户、员工、伙伴、合规、财务、物流、渠道、营销、制造、报表、标签、指标、分析、资产、实时……），基本能覆盖商务逻辑图里 90% 的节点。

## 四、关键决定：不做模板复制，做参数化

拆完之后有两条路：

**路线 A：截好图，当素材库。** 简单，但一改就废，导出就是图片，文字不可编辑。

**路线 B：参数化。** 每个原子只描述"怎么画"，参数是层数、条目、行列、配色；一份 JSON 同时产出矢量图。

我选了 B。理由很实际：**交付物必须能改。**

所以每个原子的定义长这样（伪代码）：

```js
{
  id: 'pyramid.levels',
  slots: ['层级（3–5，自上而下）'],
  gen(s, pal, c) {
    // 按层数算每层宽度、位置、颜色
    // 画等距板的三个面：顶面 / 左侧 / 右侧
  }
}
```

调用方只写：

```json
{ "id": "pyramid.levels", "content": { "items": [
  { "title": "战略目标" }, { "title": "业务能力" },
  { "title": "平台支撑" }, { "title": "数据底座" }
] } }
```

就能得到一页图；改一个参数，整页重排。

## 五、技术上真正难的四个地方

看着简单，做起来有四个坑：

### 1. PowerPoint 没有渐变和阴影的 API

`python-pptx` 只能平涂。想让方块有渐变、发光、投影，得**直接往 `spPr` 里注入 OOXML**：

```xml
<a:gradFill><a:gsLst>…</a:gsLst><a:lin ang="5400000"/></a:gradFill>
<a:effectLst><a:glow rad="190500"><a:srgbClr val="1E63E9"/></a:glow></a:effectLst>
```

注入之后，SVG 端也要有等价实现（`<linearGradient>` + `<feGaussianBlur>`），否则网页版和 PPT 版会长得不一样。

### 2. 文字沿路径？PowerPoint 不支持

模板里环形的标签是**沿弧排字**的。PowerPoint 至今没有 text-on-path。

唯一的办法是**逐字定位、逐字旋转**：每个字一个文本框，按弧长算角度，下半圈还要自动翻向。好处是——在 PPT 里每个字都能改。

### 3. 原子要"活"在两条渲染管线上

同一份场景 JSON：

```
scene JSON ──┬──> SVG（网页 / 预览 / 长图）
             └──> PPTX（原生形状，可编辑）
```

两边能力不对等：SVG 能做滤镜、能做渐变描边；PPTX 只能近似。所以每个新特性都要问一句：**PPTX 里能等价实现吗？** 不能的话，就得换画法（比如径向渐变用多层圆叠）。

### 4. 排版自检比画图更重要

80 页里最容易出的错不是画错，是**文字溢出、元素越界、文本框重叠**。

所以我写了一个 lint：逐页扫描每个形状，检查越界、按字宽估算溢出、检测文本框重叠率。

现在的状态：**44 原子图鉴 44 页、1.0 雏形 24 页、80 页验收册 80 页，lint 全部 0 问题。**

## 附：这套东西的边界

它**不是**模板复制品，也不是"AI 一键生成 PPT"。

它是一套**图形语法**：给你 44 个词、15 种句式和 8 套整页版式，你自己拼出想要的图；拼完导到 PowerPoint 里还能继续改。

如果你也在做咨询、方案、架构图，被"画图-改图-重画"折磨过，这套东西应该能省下不少时间。
